# ReadyRepair3D 技术文档：代码如何运行

文档说明当前上交包中主链路的实际运行方式。不涉及界面截图或演示素材，只讲清从输入提示词到输出 `final.glb` 的执行过程。

项目路径约定：将本包放在 Linux 服务器上的任意目录（推荐 `/root/r3dguard` 或自行设定），下文用「项目根目录」指该位置。

---

## 一、系统在做什么

ReadyRepair3D 不重新训练大型三维生成模型，而是在现有文生图与图生三维能力外包一层「质量闭环」：

1. 用中文提示词生成多张二维候选图；
2. 在生成三维之前先筛选，只把最值得投入算力的候选送进三维后端；
3. 对生成的三维结果做自动质量评分并选优；
4. 必要时做可回退的安全修复；
5. 若一轮仍不达标，可用新种子再跑一轮，最后在多轮结果中择优交付。

一句话概括：**先判断值不值得生成，再决定如何安全修复。**

---

## 二、运行前提

### 2.1 硬件与系统

主链路按 Linux + NVIDIA GPU 设计（原实验环境为单卡 A100 40GB）。脚本为 bash，不能在纯 Windows 图形界面下直接当作“双击运行”使用；可在 Linux 服务器或等价环境中执行。

### 2.2 软件环境

需要两个 Conda 环境（名称沿用历史配置）：

- `trellis2`：文生图（SANA）、Ready3D 特征提取与二维筛选；
- `hunyuan21`：Hunyuan3D-2.1 三维生成、八视角渲染、三维质量评分、Repair3D。

项目根目录提供激活脚本：

- `activate_sana.sh`（兼容别名 `activate.sh`）激活 `trellis2`；
- `activate_hunyuan21.sh`激活 `hunyuan21`。

另需可用的 Blender（用于网格检查与渲染相关步骤）。

### 2.3 第三方模型（本包不包含权重）

运行时默认从 `项目根目录/models/` 读取权重，主要包括：

- SANA 1.5（生成 4 张候选图）；
- Qwen3（主链路固定启用，用于中文提示词保守优化）；
- DINOv2、Depth Anything、BiRefNet（Ready3D 特征与三维质量评分）；
- Hunyuan3D-2.1 仓库与模型权重（主三维后端）。

本包自带的小型检查点只有 Ready3D V2：`checkpoints/ready3d_v2/ready3d_v2.joblib`。

### 2.4 配置与路径

- 质量阈值与校准文件优先使用：`config/quality_v2_calibration.json`（冻结阈值约 0.8069）。
- 脚本通过 `ops/_env.sh` 自动定位项目根目录；也可用环境变量覆盖：
  - `R3DGUARD_HOME`：项目根目录；
  - `R3DGUARD_MODELS`：模型目录（默认 `$R3DGUARD_HOME/models`）。

## 三、怎么启动

### 3.1 最简入口

在项目根目录执行：

```bash
bash run_demo.sh "一个蓝白陶瓷茶壶，完整主体，干净背景"
```

该命令会调用完整质量闭环主入口，默认输出到 `outputs/demo`，默认种子 `20260722`。

### 3.2 完整主入口

```bash
bash ops/run_full_quality_pipeline.sh \
  --prompt "你的中文提示词" \
  --output-dir ./outputs/某次实验名 \
  --seed 20260722
```

可选参数 `--quality-threshold`；若不传，则从校准文件读取冻结阈值。

### 3.3 入口之间的调用关系

自外向内共三层：

1. `run_demo.sh`  
   只负责设好项目根目录，并转调下一层。

2. `ops/run_full_quality_pipeline.sh`（完整闭环）  
   - 先跑第 1 轮：`ops/run_repaired_quality_round.sh`；  
   - 若第 1 轮未达到质量阈值，则用 `seed+1000` 再跑第 2 轮；  
   - 最后用 `ops/select_best_round.py` 在已有轮次中选优，写出最终交付物。

3. `ops/run_repaired_quality_round.sh`（单轮）  
   - 先跑 Stage1：`ops/run_top2_dual3d_stage1.sh`（从提示词到选出一个三维 GLB）；  
   - 再跑 Repair3D：`ops/run_repair3d_auto.py`；  
   - 若修复被接受，则对修复后的 GLB 再渲染、再评分；  
   - 最后由 `ops/finalize_repaired_round.py` 生成本轮 `round_final/final.glb` 与 `round_report.json`。

因此：**理解运行，关键看 Stage1 + Repair + 多轮择优。**

---

## 四、单轮主链路逐步说明（Stage1）

`ops/run_top2_dual3d_stage1.sh` 是单轮里最核心的流水线。它按阶段推进，并用 `COMPLETE` 标记实现断点续跑：某一阶段已成功则跳过。

设输出目录为 `OUTPUT_DIR`，主要子目录如下。

### 步骤 1：优化中文提示词并生成 4 张二维候选

- 环境：`activate.sh` / `activate_sana.sh`（`trellis2`）
- 提示词优化：`ops/optimize_chinese_prompts.py`
- 候选生成：`ops/generate_sana_from_optimized_prompts.py`
- 输入：中文提示词、随机种子
- 中间输出：`OUTPUT_DIR/optimized_prompt.jsonl`（1条可直接进入流水线的优化提示词）
- 图像输出：`OUTPUT_DIR/candidates/`，其中 `manifest.jsonl` 应有 4 行（4 个候选）

Qwen3 严格保留主体、数量、颜色、材质与结构，只补充完整主体、单物体、居中构图、干净背景等三维重建约束。优化进程结束后再启动 SANA，避免两个大模型同时占用显存；用户入口仍只需提供原始 `--prompt`。

### 步骤 2：提取 Ready3D 特征

- 环境：同二维侧
- 脚本：`ops/extract_ready3d_features.py`
- 输入：候选 `manifest.jsonl`
- 输出：`OUTPUT_DIR/features/`（含 `features.jsonl`、`dino_embeddings.npy` 等）

特征用于后续结构门判断与质量预测，依赖 DINOv2、深度等视觉模型。

### 步骤 3：结构门 + Ready3D Top-2 筛选

- 脚本：`scripts/score_external64.py`（加载 `checkpoints/ready3d_v2/ready3d_v2.joblib`，`--top-k 2`）
- 随后：`ops/build_selected_manifest.py` 写出入选清单
- 输出：
  - `OUTPUT_DIR/ready3d/predictions.jsonl`（每张候选的预测分与是否入选）
  - `OUTPUT_DIR/selected_manifest.jsonl`（应恰好 2 行）

含义：4 张图里只保留预测下游三维质量最高的 2 张，再进入昂贵的三维生成，以节省 GPU。

### 步骤 4：Hunyuan3D 生成两个 GLB

- 环境：切换为 `activate_hunyuan21.sh`
- 脚本：`ops/run_hunyuan_ready3d.py`
- 输入：上一步的 2 条入选二维样本
- 输出：`OUTPUT_DIR/hunyuan/glb/` 下应有 2 个 GLB

### 步骤 5：八视角渲染

- 脚本：`ops/render_hunyuan_outputs.py`
- 输出：`OUTPUT_DIR/renders/`
- 校验：每个 GLB 8 个视角，两套合计 16 张 `shaded_*.png`

### 步骤 6：自动三维质量评分（Auto3D / Quality V2）

- 脚本：`ops/score_hunyuan_outputs.py`
- 输入：GLB 状态、渲染图、校准文件
- 输出：`OUTPUT_DIR/quality_v2/quality_labels.jsonl`（2 行）

评分综合「与输入图的匹配程度」和「网格几何健康度」等自动指标，并按冻结校准做归一化，得到 `quality_score_v2`。合格与否再与阈值（约 0.8069）比较。

### 步骤 7：在两个三维结果中选优

- 脚本：`ops/select_best_hunyuan.py`
- 输出：
  - `OUTPUT_DIR/selected_3d/final.glb`（本轮 Stage1 优胜 GLB）
  - `OUTPUT_DIR/selected_3d/selection_report.json`
  - Stage1 级 `pipeline_summary.json`

至此，单轮「提示词 → Top-2 三维选优」结束，尚未经过 Repair。

---

## 五、Repair3D 与单轮收口

在 `run_repaired_quality_round.sh` 中，Stage1 完成后继续：

### 5.1 安全修复

- 脚本：`ops/run_repair3d_auto.py`
- 输入：`selected_3d/final.glb`
- 输出：`OUTPUT_DIR/repair3d/final.glb` 与 `repair_report.json`

当前部署默认是 **safe_fallback**：

- 若学习式动作模型检查点不存在（本上交包默认不启用 Repair V2/V3 检查点），则走确定性安全规则；
- 对网格做可加载性、主体完整性、非流形、破洞等检查；
- 只有在规则认为有必要且后续能证明不伤质量时，才接受修改；否则保留原 GLB。

正式口径强调：**可验证改善才修改，否则回退原件。**

### 5.2 修复后复评分（条件执行）

若修复报告显示 `accepted=true`，则：

1. `ops/build_post_repair_status.py` 登记修复后资产；
2. 再次渲染；
3. 再次 `score_hunyuan_outputs.py` 打分。

若未接受修复，则跳过该分支。

### 5.3 生成本轮最终结果

- 脚本：`ops/finalize_repaired_round.py`
- 输出：`OUTPUT_DIR/round_final/final.glb`、`round_report.json`

`round_report.json` 中包含本轮最终质量分、是否达到阈值、Repair 动作等信息，供外层多轮择优使用。

---

## 六、多轮择优与最终交付

回到 `run_full_quality_pipeline.sh`：

1. 执行 `round_1`；
2. 读取 `round_1/round_final/round_report.json`，判断是否 `meets_quality_threshold`；
3. 若不达标，再跑 `round_2`（种子为原种子 + 1000）；
4. 调用 `ops/select_best_round.py`，在已有轮次报告中选最好一轮；
5. 在用户指定的总输出目录写出：
   - `final.glb`：最终交付三维资产；
   - `final_report.json`：择优说明；
   - `pipeline_summary.json`：整次请求的汇总（提示词、种子、阈值、轮次、耗时等）；
   - 成功时还会落 `PIPELINE_COMPLETE` 标记。

---

## 七、一次完整运行的数据流（文字版）

用户给出中文提示词与种子后，系统大致按下列顺序产生数据：

提示词  
→ 4 张 SANA 候选图及清单  
→ 每张图的 Ready3D 特征与预测分  
→ 入选的 2 张图  
→ 2 个 Hunyuan GLB  
→ 16 张八视角渲染  
→ 2 条三维质量标签  
→ 1 个 Stage1 优胜 GLB  
→ Repair 报告与（可能的）修复后 GLB  
→ 本轮 `round_final`  
→（可选第二轮重复上述过程）  
→ 跨轮选优后的 `final.glb` 与报告

各阶段目录相对独立，并用 `COMPLETE` 文件标记完成，因此中断后在同一 `output-dir` 上重跑，一般会从失败阶段继续，而不是全部重来。

## 九、如何确认跑通

一次成功运行后，至少应看到：

1. 总输出目录下存在非空的 `final.glb`；
2. 存在 `final_report.json` 与 `pipeline_summary.json`；
3. 各关键子阶段存在对应 `COMPLETE` 或明确的报告文件；
4. 可用 `python ops/verify_glb.py /path/to/final.glb` 做基本加载检查（需相应环境）。

交付验收还可执行：

```bash
bash verify_delivery.sh
```

该命令激活 `hunyuan21` 并运行 `pytest`。涉及 CUDA、Blender、大模型权重的用例，在未配齐环境时无法全部通过，这属于环境依赖，而不是主链路脚本缺失。

---

## 十、运行边界与注意点

1. 本包是「流水线代码 + 小型检查点 + 实验摘要」，不是「开箱即用的全权重一体包」。没有第三方模型时，主链路无法真正生成。
2. 正式修复策略是 safe_fallback；学习式 Repair 动作模型不是默认启用路径。
3. 主入口三层脚本已支持相对项目根目录定位；部分历史辅助脚本仍可能写死旧服务器路径，但不影响上述主链路启动方式。
4. Windows 本机通常只适合阅读与打包代码；实际推理请在 Linux GPU 环境执行。

---

## 十一、最短操作清单

1. 在 Linux GPU 机器上放置本项目，安装 `trellis2`、`hunyuan21`、Blender。  
2. 按 `THIRD_PARTY_MODELS.md` 准备模型到 `models/`。  
3. 确认存在 `config/quality_v2_calibration.json` 与 `checkpoints/ready3d_v2/ready3d_v2.joblib`。  
4. 执行：`bash run_demo.sh "你的中文提示词"`。  
5. 在输出目录取用 `final.glb` 与报告文件。

以上即当前代码的实际运行方式。
